# GraphQL API for a mobile fitness app

**Client:** FitLoop (synthetic) | **Industry:** Health & fitness | **Duration:** 6 weeks | **Date:** 2024-04

## The problem
The client was a mobile team blocked by 30 bespoke REST endpoints.

## What I did
My approach: a single typed schema with data loaders and field-level auth. The main stack was GraphQL, Node.js, TypeScript. Under the hood this meant a modular, decorator-based TypeScript backend. It also needed a relational database with proper migrations and indexes. Behind the scenes I set up a containerised build that runs the same everywhere. 

## Result
The work mobile releases went from monthly to weekly.

## What I learned
Write the data checks before the model or the UI; most surprises came from the data.
